## Контролер

Чиста фабрика `CashflowSync.createRefreshController` в `index.html` між
маркерами `LIVE REFRESH CONTROLLER`; Node-тести витягують той самий блок.
Збережено single-file фронтенд без npm/build і додаткового script asset.
Немає побічної роботи при визначенні фабрики.
`start`, `stop`, `request(resources, reason)`; інʼєкції годинника, таймерів,
стану мережі, підписки, refresh і status для контрольованих тестів.

- Одна активна операція. Пачка подій за 400 мс обʼєднується; події під час
  запиту створюють одну наступну пачку. Promise належить потрібній пачці.
- Resume-trigger спільний для focus/visibility/online: 15 с, видима вкладка
  та online. Пропущені прихованою вкладкою зміни не губляться.
- Mono: від часу попередньої спроби, включно з помилкою, не частіше 60 с.
  DB-події його не запускають, щоб UPDATE банку не утворював цикл.
- `stop` синхронно інвалідує callbacks, чистить listeners/channel/timers;
  старі запити не змінюють React-стан. Новий користувач — новий контролер.
- Стан каналу відділений від свіжості даних. `SUBSCRIBED` не означає
  «Оновлено». Помилка/невідомий статус дають видимий fallback і retry.
- Демо чи відсутня дозволена сесія: нуль підписок, таймерів і мережі.

## Інтеграція даних

Усі повторні читання одного ресурсу, включно з initial load, local mutation,
retry й Realtime, використовують спільний awaitable шлях. Loader повертає
успіх/помилку явно; часткові сторінки не замінюють повний список. Кожен
setter, nested signed URL і Mono callback перевіряє auth generation та
актуальність ресурсу/періоду. Старий місяць не підміняє поточний.

Порядок full refresh: категорії/групи, зарплата, рахунки, постійні й
розстрочки → залежні вибірки операцій → заощадження/цілі. Залежні межі
будуються з фактично завантажених налаштувань і рахунків, не старого closure.
Не залишати дублюючі запити через старі `[dbTx]`-ефекти. Background goals
refresh лише читає; створення типових цілей — окремий initial-only шлях.

Payload — сигнал повторного читання, не джерело фінансових сум. Його не
записують у журнали. Публікація охоплює transactions, accounts,
fixed_payments, credits, categories, category_groups, salary_config,
savings_log, goals. RLS, policies, privileges та replica identity не змінюються.

## Ворота

Fake-clock Node: debounce, одна пачка після поточної, waiters, 15/60 с,
помилки, stale, прихована вкладка, offline, reconnect, disabled та cleanup.
Browser mock: подія → змінені дані/суми; delayed request після logout або
зміни місяця ігнорується; error не показує успіх; goals background не сіє.
Повний регресійний прогін після стабілізації, візуальна перевірка, Pages
для точного коміту, збіг живих файлів і справжній LoginScreen.
