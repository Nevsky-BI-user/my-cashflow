# Команда агентів для наступної задачі

## Стартовий запит

> Прочитай HANDOFF.md, TEAM.md та AGENTS.md. Працюй командою до трьох
> агентів одночасно: координатор, виконавець, незалежний ревʼюер/тестувальник.
> Моя задача: [результат і конкретний приклад проблеми]. Спершу визнач
> критерії готовності, потім виконай зміну й перевір її. Зберігай чинну
> палітру та фінансовий контракт. Не розширюй задачу. Для деплою: [дозволяю
> після перевірок / лише підготувати локально]. Наприкінці онови HANDOFF.md.

## Ролі

| Роль | Відповідальність | Доступний агент |
|---|---|---|
| Координатор | Вимоги, рішення, межі, інтеграція, звіт і реліз | Головна сесія; складна декомпозиція — `task-planner` |
| Виконавець | Код за точним брифом у визначених файлах | `exec-sonnet`; механіка — `exec-haiku`; складний баг — `exec-opus` |
| Перевірка | Незалежне ревʼю або відтворення сценарію | `code_reviewer`, `test_engineer`; UX-аудит — `ux-baseline-auditor` |

Сильна модель потрібна для неоднозначної фінансової логіки, складного
дефекту й ревʼю. Типові CSS-правки та механічні заміни не потребують її.
Ролі можуть виконуватися послідовно: не тримати окремого агента для кожного файлу.

## Робочий цикл

1. Одна конкретна зміна та 3–5 критеріїв готовності. Для дизайну — скриншот
   потрібного екрана/ширини й перелік змін; для суми — приклад очікуваного розрахунку.
2. Самодостатній бриф: контекст, дозволені файли, що зробити, що перевірити,
   команда перевірки й формат звіту. Кожен файл має одного активного власника.
3. Виконавець вносить зміни; дешеві перевірки перед читанням великих diff.
   Дві невдалі спроби — передати координатору причину й варіанти рішення.
4. Ревʼюер перевіряє результат незалежно. Повторні тести — для знайденого
   ризику або обовʼязкового релізного барʼєра, а не нескінченні цикли полірування.
5. Координатор збирає результат, запускає потрібні ворота, робить дозволений
   деплой, перевіряє опубліковану версію й закриває свої фонові процеси.

Для одного рядка чи дрібної правки команда не потрібна.
Не запускати паралельно тести, що переписують спільне превʼю, під час
редагування `index.html`. Фінансові приклади й автотести — на синтетичних даних.
