# Telegram-бот: підключення

Бот приватний: не публікувати в каталозі, не вмикати inline-режим. Привʼязка до акаунта
лише одноразовим кодом із застосунку (email/password у боті не буває).

## 1. Створити бота

1. У Telegram відкрити @BotFather, надіслати `/newbot`, задати назву й username.
2. Скопіювати токен виду `123456789:AAH...` (він показується один раз).
3. `/setprivacy` -> Enable (бот читає лише повідомлення, адресовані йому).
4. `/setuserpic` -> вибрати бота -> надіслати `assets/bot-avatar.png` (аватарку через API поставити не можна).
   Назву «Сімейний Кешфлоу», опис і меню команд бот отримує сам при натисканні «Підключити бота».

## 2. Секрети (PowerShell, у теці репозиторію, по одній команді)

Токен вставити замість `<TOKEN>`; секрет webhook генерується на місці:

```
npx -y supabase@latest secrets set TELEGRAM_BOT_TOKEN=<TOKEN>
```

```
npx -y supabase@latest secrets set TELEGRAM_WEBHOOK_SECRET=$([guid]::NewGuid().ToString())
```

Для чеків і автокатегоризації ще ключ Claude API (console.anthropic.com):

```
npx -y supabase@latest secrets set CLAUDE_API_KEY=<KEY>
```

## 3. Міграція й деплой

```
npx -y supabase@latest db push
```

```
npx -y supabase@latest functions deploy telegram-webhook telegram-setup categorize categorize-batch
```

У Dashboard -> Storage має бути приватний bucket `receipts` (для фото чеків).

## 4. Реєстрація webhook і привʼязка

1. У застосунку: шестерня -> блок Telegram -> «Підключити бота». Відповідь «Бот підключено: @ім'я».
2. «Код для Telegram» -> у боті надіслати `/start 123456` (код діє 10 хв).
3. Перевірка: `250 кава` -> «✅ Витрата: 250,00 ₴, кава · Ощадбанк» і кнопки інших рахунків; `/last`, `/balance`.

## Кнопки й додавання операцій

Після привʼязки надішліть `/start` або `/menu`, щоб показати головну клавіатуру. Вона містить доходи, витрати, пʼять звітів, останні операції, допомогу, застосунок, повернення до меню та скасування.

- Дохід текстом: **➕ Дохід → ✍️ Текстом → `1500 повернення коштів`**. Плюс не потрібен: тип уже вибрано.
- Дохід зі скриншота: **➕ Дохід → 📷 Зображенням → надіслати фото**. Бот приймає лише підтверджені зображенням доходи з сумою, валютою й датою. Один переказ також розпізнається як операція. Змішаний список, витрата або звичайний магазинний чек не перетворюються на дохід; нічого не записується, можна повторити фото.
- Витрата: **➖ Витрата → ✍️ Текстом** або **📷 Зображенням**. Текст: `250 кава`; зображення: цілий чек із підсумком або список лише витрат.
- **⬅️ Головне меню**, допомога, застосунок і звіти завершують незбережене введення. **✖ Скасувати** скасовує поточний крок чи підтвердження лише після успішного збереження стану.

На введення є 10 хвилин. Після завершення цього часу наступне повідомлення нічого не записує: виберіть тип знову. Знак суми, який суперечить вибраному типу, відхиляється. Після помилки розпізнавання чи запису режим залишається активним і бот показує підказку для повтору. Файли-документи, PDF, аудіо та відео не підтримуються цим кроком; надсилайте зображення як фото.

Якщо бот уже чекає підтвердження схожого доходу чи збирає довгий чек, спочатку завершіть або скасуйте ту дію. Звіти її не стирають. **✅ Так, додати** підтверджує лише вже підготовлену операцію; у порожньому кроці введення кнопка нічого не записує. Для довгих чеків лишається звичайне надсилання фото без вибору режиму.

## Швидке введення й команди

| Текст | Дія |
|---|---|
| `250 кава` | витрата 250 ₴ з описом «кава» |
| `+51000 зарплата` | дохід |
| `/income 51000 зарплата` або `/дохід ...` | дохід |
| `/income`, `/дохід`, `/expense` без суми | почати вибір тексту чи зображення |
| `/expense 250 кава` | витрата |
| `/yes` | підтвердити дохід, схожий на запис Monobank (бот сам запитає) |
| фото чека | сума й магазин розпізнаються, запис із чеком |
| скриншот кількох операцій або чеків | до 20 окремих доходів/витрат у гривнях, з вибором рахунку для кожного |
| `/balance` | доходи, витрати, баланс за поточний місяць |
| `/last` | останні 5 записів |
| `/help` | підказка |
| `/menu` або `меню` | головна клавіатура |
| `/app` | звичайне посилання на застосунок |
| `/no`, `/cancel` | скасувати поточну дію |

У кнопковому текстовому режимі підтримуються групи тисяч: `1 500 зарплата`, `12 345,67 зарплата`, зокрема з нерозривним пробілом. Кожна група після першої має містити рівно три цифри; неправильне групування відхиляється без запису. Опис у цьому режимі має починатися не з цифри, щоб його не сплутати із сумою. Для швидкого введення поза режимом і команд із сумою використовуйте числа без пробілів-роздільників, наприклад `1250 кава`.

## Рахунок операції

Операція з бота привʼязується до рахунку (`transactions.account_id`), але за замовчуванням рахунок підставляється лише доходам.

- Слово-ключ на початку або в кінці опису: `ощад`, `приват`, `готівка` (`кеш`, `cash`), без урахування регістру; або початок назви рахунку від 3 літер (`ощадбанк`). Слово вирізається з опису: `250 кава приват` -> витрата «кава» з ПриватБанку.
- Для текстових операцій рахунок Monobank (з `mono_account_id`) бот не пропонує і не обирає: його операції приходять з банку самі. Для фото та скриншотів доступні всі активні рахунки; картка може визначитися за зображенням незалежно від платіжної системи. Повторно імпортована банківська операція може створити дублікат.
- Текстова витрата без слова-ключа записується без рахунку (`account_id = null`), відповідь: «✅ Витрата: 50 ₴, кава · рахунок не вибрано. З якого рахунку?» і кнопки всіх активних рахунків, крім Monobank. Після натискання повідомлення редагується («· Ощадбанк»). Для фото рахунок може визначитися із зображення, а підпис має пріоритет.
- Дохід без слова-ключа іде на рахунок зарплати (`is_salary`), далі перший активний дебетовий; кнопки змінюють рахунок.
- Для фото чека слово пишеться в підписі фото. У довгому чеку підпис наступної частини може змінити рахунок першої.
- Після вибору рахунку бот показує його назву й прибирає всі кнопки вибору з повідомлення. Після `/yes` кнопки приходять окремим повідомленням «Змінити рахунок:», щоб повернулась основна клавіатура.
- Нагадування в `/balance`: якщо за останні 60 днів є витрати з Telegram чи застосунку без рахунку, додається рядок «⚠️ Без рахунку: N операцій на X ₴, виберіть рахунок під повідомленнями або в застосунку». Ці операції (створені після найстарішого `balance_updated_at` ручних рахунків) віднімаються від власних коштів у «Вільно до виплати», доходи без рахунку додаються, тож цифра не завищується, доки рахунок не вибрано.
- Похідний баланс ручних рахунків (без звʼязку з Monobank API): до збереженого балансу додаються операції з цим рахунком, створені після останнього ручного оновлення балансу (`balance_updated_at`). Дебет і готівка: баланс мінус витрати плюс доходи; кредитна: борг плюс витрати мінус доходи. Тобто витрати з бота зменшують баланс Ощаду до наступного ручного оновлення повзунком. `/balance` показує рядок «Рахунки: ...» з такими балансами, `/last` назву рахунку в дужках.
- Поріг мінімальних витрат (поля `min_spend`, `min_spend_fee` рахунку, міграція 21): `/balance` додає рядок «Ощадбанк: витрачено 1 763 з 15 000 за жовтень, ще 13 237 до 31.10, інакше комісія 400 ₴» (або «поріг 15 000 досягнуто»); рахуються витрати з цим рахунком за датою в поточному місяці.
- Кнопки працюють, лише якщо webhook приймає `callback_query` (параметр `allowed_updates` у `setWebhook`).

## Кілька операцій на одному скриншоті

Надішліть одне фото або скриншот зі списком операцій чи кількома незалежними чеками. Бот записує кожну операцію окремо: сума, дохід/витрата, опис і дата; зображення спільне для всіх записів. Товарні позиції одного чека, баланс і підсумок списку не стають окремими операціями.

Підтримуються до 20 чітко видимих операцій у гривнях. Дата кожної операції береться з її рядка або заголовка групи на скриншоті. Видимі «сьогодні» та «вчора» визначаються відносно дати повідомлення Telegram за Києвом; повторна доставка повідомлення не змінює цю опору. Дата без року, наприклад «пн 19 жовтня», отримує найближчий минулий або поточний рік, щоб не виходити за дату повідомлення; видимий день тижня має збігатися. Тому скриншоти з відносними датами надсилайте в день створення, а для давніх обирайте зображення з повною датою. Відсутню дату бот не замінює сьогоднішньою. Якщо список неповний, сума, напрямок або дата нечитабельні, валюта інша чи дата некоректна, нічого не записується: надішліть чіткіший фрагмент, де видно дату. Повні історичні дати зберігаються без обмеження 45 днями; майбутня дата не приймається.

Підтримуються ISO-дати, ДД.ММ.РРРР, ДД/ММ/РРРР, ДД.ММ.РР, дати без року, українські назви всіх місяців і поширені скорочення. Двозначний рік належить століттю дати повідомлення: наприклад, у XXI столітті «24» означає 2024. Майбутній рік не переноситься на попереднє століття. Для 29 лютого без року бот знаходить найближчий минулий високосний рік; неправильний день тижня не виправляє підбором іншого року. Повні й короткі назви днів тижня перевіряються для числових і текстових дат. Жодна дата не може бути пізнішою за дату повідомлення або поточний день.

Спільний заголовок вибраної картки застосовується до операцій усіх груп дат. Явні інші реквізити окремої операції мають пріоритет; суперечливі ознаки не змішуються.

Бот зіставляє будь-які видимі останні чотири цифри картки з полем «Останні 4 цифри» активних безготівкових рахунків. Початкові нулі зберігаються. Якщо поле не заповнено, видимі цифри не дозволяють автоматично вибрати рахунок; цифри в назві рахунку для цього не використовуються. Відомий банк звужує пошук; без відомого банку достатньо єдиного точного збігу цифр. За кількох збігів або відсутності збігу бот залишає рахунок невибраним. Якщо на зображенні цифр немає, можна автоматично вибрати лише єдиний активний безготівковий рахунок відомого банку. Visa чи Mastercard не обмежують вибір. Слово-ключ у підписі має пріоритет і задає спільний рахунок для всього скриншота. Для довгого чека зберігається рахунок першої частини; новий підпис може його змінити.

Повтор доставки того самого повідомлення Telegram не створює дублів. Перед записом фото бот також шукає схожі операції серед усіх джерел: та сама сума до копійки й тип, дата в межах ±3 днів, а також той самий вибраний рахунок або однаковий опис без різниці регістру та розділових знаків. Якщо рахунок невідомий, потрібен збіг опису. Така перевірка діє і між рядками одного скриншота. Якщо є підозра на дубль або перевірка недоступна, весь скриншот не записується; бот показує дату й суму збігу. Це може зупинити й справді повторну покупку на таку саму суму — перевірте записи.

Перевірка перед записом не блокує одночасний імпорт з іншого джерела або паралельну обробку двох різних повідомлень. Для такого випадку без зміни бази даних гарантії від дублів немає; не надсилайте той самий скриншот одночасно кілька разів.

Якщо бот уже збирає довгий чек, спочатку завершіть його або скасуйте через `/no`, а потім надішліть скриншот.

## Довгі чеки

Довгий чек можна надіслати кількома фото. Правило: якщо на фото немає рядка підсумку (СУМА, До сплати, Разом), бот нічого не записує, а чекає наступне фото 10 хв. Коли приходить фото з підсумком, бот розпізнає всі частини разом і записує одну витрату на суму з підсумку; усі фото зберігаються при записі. Для запису потрібна дата операції хоча б на одній із частин. `/yes` після частини без підсумку записує чек за орієнтовною сумою позицій, лише якщо відомі сума й дата; `/no` скасовує збирання. Через 10 хв без нового фото збирання протухає, частини в Storage лишаються.

Підозрілий результат розпізнавання (помилка чи жодної суми, нечітке фото, підсумок розходиться із сумою позицій більше ніж на max(1 ₴, 2 %), неправдоподібна дата) бот один раз перечитує тими самими фото сильнішою моделлю `claude-sonnet-5-5` і бере її відповідь, якщо вона придатна; так само для кожної частини довгого чека.

Відоме обмеження: якщо фото надіслано альбомом (одним повідомленням з кількох фото) і фото з підсумком обробилось раніше за фото без підсумку, чек не збережеться сам: частина без підсумку лишиться в очікуванні й протухне за 10 хв. Тоді надішліть фото з підсумком ще раз окремим повідомленням.

## Якщо не працює

- 403 у логах `telegram-webhook`: секрет у Telegram не збігається з `TELEGRAM_WEBHOOK_SECRET`; натиснути «Підключити бота» ще раз.
- «Доступ закритий»: chat_id не привʼязаний; згенерувати код і надіслати `/start <код>`.
- Логи: Dashboard -> Edge Functions -> telegram-webhook -> Logs.


### Постійні платежі та дострокова оплата

Створіть платіж у застосунку. Для щорічного платежу оберіть «Щороку», місяць і день; 29 лютого в невисокосний рік переноситься на 28 лютого.

Бот привʼязує текстові витрати й чеки до єдиного активного платежу за назвою. Назви Claude, Клод та Anthropic розпізнаються як той самий сервіс. Сума сама по собі не є підставою для привʼязки. Якщо є кілька збігів, платіж уже оплачено або в описі вказано «наперед» чи конкретний місяць, оберіть зобовʼязання вручну.

Після збереження витрати натисніть **«Привʼязати обовʼязковий платіж»**, потім назву й дату зобовʼязання. Це дозволяє, наприклад, у грудні зарахувати оплату оренди за січень. Дата фактичної витрати, сума та рахунок зберігаються.

Для вже записаної звичайної витрати надішліть `/link`: бот покаже 10 останніх ваших непривʼязаних витрат. Для старішої операції використайте `/link <id операції>`. Бот змінює привʼязку наявного запису і не створює другу витрату. Раніше збережені дані автоматично не перекласифіковуються.
