# Telegram-бот: підключення

Бот приватний: не публікувати в каталозі, не вмикати inline-режим. Привʼязка до акаунта
лише одноразовим кодом із застосунку (email/password у боті не буває).

## 1. Створити бота

1. У Telegram відкрити @BotFather, надіслати `/newbot`, задати назву й username.
2. Скопіювати токен виду `123456789:AAH...` (він показується один раз).
3. `/setprivacy` -> Enable (бот читає лише повідомлення, адресовані йому).
4. `/setuserpic` -> вибрати бота -> надіслати `assets/bot-avatar.png` (аватарку через API поставити не можна).
   Назву «Сімейний Кешфлоу», опис і меню команд бот отримує сам при натисканні «Підключити бота».

## 2. Секрети (PowerShell, у теці репозиторію, по одній команді)

Токен вставити замість `<TOKEN>`; секрет webhook генерується на місці:

```
npx -y supabase@latest secrets set TELEGRAM_BOT_TOKEN=<TOKEN>
```

```
npx -y supabase@latest secrets set TELEGRAM_WEBHOOK_SECRET=$([guid]::NewGuid().ToString())
```

Для чеків і автокатегоризації ще ключ Claude API (console.anthropic.com):

```
npx -y supabase@latest secrets set CLAUDE_API_KEY=<KEY>
```

## 3. Міграція й деплой

```
npx -y supabase@latest db push
```

```
npx -y supabase@latest functions deploy telegram-webhook telegram-setup categorize categorize-batch
```

У Dashboard -> Storage має бути приватний bucket `receipts` (для фото чеків).

## 4. Реєстрація webhook і привʼязка

1. У застосунку: шестерня -> блок Telegram -> «Підключити бота». Відповідь «Бот підключено: @ім'я».
2. «Код для Telegram» -> у боті надіслати `/start 123456` (код діє 10 хв).
3. Перевірка: `250 кава` -> «✅ Витрата: 250,00 ₴, кава · Ощадбанк» і кнопки інших рахунків; `/last`, `/balance`.

## Команди бота

| Текст | Дія |
|---|---|
| `250 кава` | витрата 250 ₴ з описом «кава» |
| `+51000 зарплата` | дохід |
| `/income 51000 зарплата` або `/дохід ...` | дохід |
| `/yes` | підтвердити дохід, схожий на запис Monobank (бот сам запитає) |
| фото чека | сума й магазин розпізнаються, запис із чеком |
| `/balance` | доходи, витрати, баланс за поточний місяць |
| `/last` | останні 5 записів |
| `/help` | підказка |

Суми без пробілів-роздільників: «1 250 кава» прочитається як 1 ₴ з описом «250 кава».

## Рахунок операції

Операція з бота привʼязується до рахунку (`transactions.account_id`), але за замовчуванням рахунок підставляється лише доходам.

- Слово-ключ на початку або в кінці опису: `ощад`, `приват`, `готівка` (`кеш`, `cash`), без урахування регістру; або початок назви рахунку від 3 літер (`ощадбанк`). Слово вирізається з опису: `250 кава приват` -> витрата «кава» з ПриватБанку.
- Рахунок Monobank (з `mono_account_id`) бот не пропонує і не обирає: його операції приходять з банку самі, інакше витрата задвоїться. Слово `моно` не є ключем і лишається в описі; кнопка Monobank відсутня, а callback на нього відхиляється.
- Витрата без слова-ключа записується без рахунку (`account_id = null`), відповідь: «✅ Витрата: 50 ₴, кава · рахунок не вибрано. З якого рахунку?» і кнопки всіх активних рахунків, крім Monobank. Після натискання повідомлення редагується («· Ощадбанк»). Те саме для довгих чеків: рахунок береться зі слова-ключа в підписі фото, інакше без рахунку.
- Дохід без слова-ключа іде на рахунок зарплати (`is_salary`), далі перший активний дебетовий; кнопки змінюють рахунок.
- Для фото чека слово пишеться в підписі фото. У довгому чеку підпис наступної частини може змінити рахунок першої.
- Після вибору рахунку кнопки лишаються (інші рахунки). Після `/yes` кнопки приходять окремим повідомленням «Змінити рахунок:», щоб повернулась основна клавіатура.
- Нагадування в `/balance`: якщо за останні 60 днів є витрати з Telegram чи застосунку без рахунку, додається рядок «⚠️ Без рахунку: N операцій на X ₴, виберіть рахунок під повідомленнями або в застосунку». Ці операції (створені після найстарішого `balance_updated_at` ручних рахунків) віднімаються від власних коштів у «Вільно до виплати», доходи без рахунку додаються, тож цифра не завищується, доки рахунок не вибрано.
- Похідний баланс ручних рахунків (без звʼязку з Monobank API): до збереженого балансу додаються операції з цим рахунком, створені після останнього ручного оновлення балансу (`balance_updated_at`). Дебет і готівка: баланс мінус витрати плюс доходи; кредитна: борг плюс витрати мінус доходи. Тобто витрати з бота зменшують баланс Ощаду до наступного ручного оновлення повзунком. `/balance` показує рядок «Рахунки: ...» з такими балансами, `/last` назву рахунку в дужках.
- Поріг мінімальних витрат (поля `min_spend`, `min_spend_fee` рахунку, міграція 21): `/balance` додає рядок «Ощадбанк: витрачено 1 763 з 15 000 за жовтень, ще 13 237 до 31.10, інакше комісія 400 ₴» (або «поріг 15 000 досягнуто»); рахуються витрати з цим рахунком за датою в поточному місяці.
- Кнопки працюють, лише якщо webhook приймає `callback_query` (параметр `allowed_updates` у `setWebhook`).

## Довгі чеки

Довгий чек можна надіслати кількома фото. Правило: якщо на фото немає рядка підсумку (СУМА, До сплати, Разом), бот нічого не записує, а чекає наступне фото 10 хв. Коли приходить фото з підсумком, бот розпізнає всі частини разом і записує одну витрату на суму з підсумку; усі фото зберігаються при записі. `/yes` після частини без підсумку записує чек за орієнтовною сумою позицій (якщо вона відома), `/no` скасовує збирання. Через 10 хв без нового фото збирання протухає, частини в Storage лишаються.

Підозрілий результат розпізнавання (помилка чи жодної суми, нечітке фото, підсумок розходиться із сумою позицій більше ніж на max(1 ₴, 2 %), неправдоподібна дата) бот один раз перечитує тими самими фото сильнішою моделлю `claude-sonnet-5-5` і бере її відповідь, якщо вона придатна; так само для кожної частини довгого чека.

Відоме обмеження: якщо фото надіслано альбомом (одним повідомленням з кількох фото) і фото з підсумком обробилось раніше за фото без підсумку, чек не збережеться сам: частина без підсумку лишиться в очікуванні й протухне за 10 хв. Тоді надішліть фото з підсумком ще раз окремим повідомленням.

## Якщо не працює

- 403 у логах `telegram-webhook`: секрет у Telegram не збігається з `TELEGRAM_WEBHOOK_SECRET`; натиснути «Підключити бота» ще раз.
- «Доступ закритий»: chat_id не привʼязаний; згенерувати код і надіслати `/start <код>`.
- Логи: Dashboard -> Edge Functions -> telegram-webhook -> Logs.
