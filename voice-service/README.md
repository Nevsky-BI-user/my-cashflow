# Мовний сервіс бота

Невелика програма для ноутбука. Поки вона працює, Telegram-бот кешфлоу:

- **розуміє голосові**: ви надсилаєте голосове питання, ноутбук перетворює його на текст (faster-whisper, модель large-v3-turbo, на відеокарті за частку секунди);
- **відповідає голосом власника**: текст відповіді ноутбук озвучує клонованим голосом (HolosTTS) і віддає боту готовий файл OGG/Opus.

Ноутбук сам звертається до Supabase (функція `voice-jobs`): «є робота?». Якщо є, бере завдання, виконує і здає результат. Відкривати порти, налаштовувати роутер чи білу IP-адресу не треба.

Програма нічого не відтворює вголос: звук лише декодується і кодується в памʼяті.

## Коли ноутбук вимкнений

Бот бачить, що ноутбук не на звʼязку (немає запитів понад 90 с), і на голосове відповідає, що зараз не може його розпізнати. Текстові повідомлення працюють як завжди. Щойно ноутбук увімкнеться і воркер стартує, голосові знову працюють.

## Де що лежить

| Що | Де |
| --- | --- |
| Код (у git, публічний) | `voice-service\` у репозиторії |
| Робоча копія коду, звідки запускається воркер | `.local\voice-service\` (копіює `install.ps1`) |
| Середовище Python | `.local\voice-service\venv` |
| Налаштування і **секрет** | `.local\voice-service\config.json` |
| Журнал | `.local\voice-service\logs\worker.log` |
| Вектор голосу | `.local\voice\voice.npy` (шлях у `config.json`, поле `voice_npy`) |
| Моделі | кеш Hugging Face у профілі користувача, вантажаться при першому запуску |

Тека `.local` не потрапляє в git. Секрет, вектор голосу і записи голосу в репозиторій не кладемо ніколи.

`config.json`:

```json
{
  "supabase_url": "https://<проєкт>.supabase.co",
  "voice_secret": "<48 символів>",
  "voice_npy": "C:\\...\\.local\\voice\\voice.npy",
  "device": "auto"
}
```

`device`: `auto` (відеокарта, а якщо не вийшло, то процесор), `cuda` або `cpu`.

## Встановлення

Потрібні Windows, Python 3.13 і git. У PowerShell із теки `voice-service`:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Скрипт створить середовище, поставить пакети (уперше кілька хвилин, близько 3 ГБ), скопіює код сервісу в `.local\voice-service` і створить `config.json` з новим секретом. Секрет він покаже **один раз**: його треба покласти в секрети Supabase, інакше сервер відповідатиме 401:

```powershell
supabase secrets set VOICE_SECRET=<секрет із виводу>
```

Загубили секрет: він лежить у `config.json`. Новий: видаліть `config.json`, запустіть `install.ps1` ще раз і оновіть `VOICE_SECRET` у Supabase.

## Запуск, стан, зупинка

Ці скрипти запускаються з `.local\voice-service` у корені репозиторію: туди їх копіює `install.ps1`, тож воркер не зникає, коли в робочій теці відкрита інша гілка. Після оновлення коду в git запустіть `install.ps1` ще раз, а потім `stop.ps1` і `start.ps1`.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
powershell -ExecutionPolicy Bypass -File .\status.ps1
powershell -ExecutionPolicy Bypass -File .\stop.ps1
```

- `start.ps1` запускає воркер у фоні без вікна. Перед роботою він вантажить і прогріває обидві моделі (до хвилини), лише потім бере завдання.
- `status.ps1` каже, чи воркер живий, і показує останні рядки журналу.
- `stop.ps1` зупиняє воркер.

Другий екземпляр не запуститься: воркер тримає замок на файл.

## Автозапуск при вході в Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\autostart.ps1
```

Створює задачу Планувальника «Family Cashflow Voice»: при вході в систему стартує воркер (без вікна консолі), після збою перезапускається до 3 разів. Вимкнути:

```powershell
powershell -ExecutionPolicy Bypass -File .\autostart.ps1 -Remove
```

## Що пише журнал

Лише службове: номер завдання, тип (`stt` чи `tts`), тривалість аудіо, час обробки, помилки (тип і місце, без тексту). Що ви сказали і що відповів бот, у журнал не потрапляє.

Типові записи:

- `401: перевірте voice_secret і годинник`: секрет у `config.json` не збігається з `VOICE_SECRET` у Supabase або годинник ноутбука збився більше ніж на 2 хвилини. Воркер чекає хвилину і пробує знову.
- `claim failed ... retry in Ns`: немає мережі чи сервер недоступний, воркер повторює з паузою від 2 до 30 с.
- `CUDA недоступна ..., розпізнавання на процесорі`: відеокарта не підхопилась; розпізнавання працює, але повільніше (8-18 с на питання).

## Обмеження

- Голосове довше 120 с: помилка «задовге аудіо».
- Текст для озвучення довший за 2000 символів: помилка «задовгий текст». Довгий текст ділиться на речення до 250 символів, між ними пауза 0,2 с.

## Перевірка

Тести без звуку і без справжнього Supabase (локальний мок-сервер на 127.0.0.1), з теки `voice-service`:

```powershell
..\.local\voice-service\venv\Scripts\python.exe -m unittest -v test_worker
```

Шлях до venv залежить від того, де лежить клон: це `.local\voice-service\venv` у корені репозиторію. Тест із моделями шукає записи `.local\voice\q01.wav` і вектор `voice.npy`; без них поставте `$env:VOICE_SKIP_MODELS = '1'`.

Заміри швидкості: `python bench.py` тим самим інтерпретатором.

## Протокол

Один ендпойнт `POST <supabase_url>/functions/v1/voice-jobs`, тіло JSON, заголовки `X-Voice-Ts` (unix-секунди) і `X-Voice-Sig` (hex HMAC-SHA256 від `"<ts>\n" + тіло` на ключі `voice_secret`). Дії: `claim` (довге очікування до 50 с, водночас знак «ноутбук на звʼязку») і `done` (результат або помилка).
